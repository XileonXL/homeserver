# bidsenseai_extractor

Temporary: not part of the house and to be removed; see
[docs/decisions.md](../../../docs/decisions.md#a-temporary-bidsense-ai-extractor-outside-the-house).

Runs `doc-extractor run --pending` from the private BidSense AI repository every night at
02:30 Europe/Madrid, as the `extractor` user, with a Claude Code subscription token and AWS
credentials from IAM Roles Anywhere (`aws_signing_helper` as `credential_process`).

- Repository: checked out over SSH with a read-only deploy key, tracking `main`
  (`bidsenseai_extractor_repo_ref`). Re-run the play to deploy the latest pushed `main`.
- Tools at pinned versions with checksums: uv, Claude Code, `aws_signing_helper`.
- Configuration in `/etc/bidsenseai-extractor/` (`env`, `alerts.env`, certificate and key).
- Web: `bidsenseai-extractor-web.timer` runs at 07:00 Europe/Madrid, after the 06:30 score Lambda.
  `/usr/local/sbin/bidsenseai-extractor-web` exports the data (`adjudication-model web-export
  --province 28`), runs `npm ci --ignore-scripts` and `npm run build` in the checkout's `web/`
  (Node.js from the pinned official tarball, without the Claude token in the environment),
  uploads `dist/` with rsync to `releases/<UTC timestamp>/` on the `bidsenseai_web` guest and
  runs `switch <timestamp>` there. The guest serves it; see the
  [bidsenseai_web README](../bidsenseai_web/README.md). The SSH key pair
  (`~/.ssh/web_deploy_key`) is generated by the play and the web guest's host key is pinned in
  `~/.ssh/web_known_hosts`.
- Removed on the previous layout: the site units, nginx and `/srv/bidsenseai` (the play deletes
  them if present).
- A failed extraction run or web build sends a Telegram message through `OnFailure=bidsenseai-extractor-alert@%n.service` (template unit; the failed unit name is passed to the alert script). `TELEGRAM_BOT_TOKEN` and
  `TELEGRAM_CHAT_ID` must both be in `.env`; run the `alerts` role first, which writes the chat id there.
- Variables and defaults: `defaults/main.yml`. Secrets and ARNs come from `.env`; see
  `.env.example`.

Run: `ansible-playbook site.yml --limit bidsenseai_extractor:bidsenseai_web`. Both are needed:
this play reads the web guest's SSH host key and the web play reads this guest's public key, so the
web guest must exist (OpenTofu) and be reachable.

## Yearly renewal

The Claude Code token (`claude setup-token`) and the end-entity certificate both last one
year. Create the new certificate with the openssl steps in the BidSense AI `infra/README.md`,
section "Homeserver extractor (IAM Roles Anywhere)", update `CLAUDE_CODE_OAUTH_TOKEN` and the
files referenced by `BIDSENSEAI_EXTRACTOR_CERT_FILE` and `BIDSENSEAI_EXTRACTOR_KEY_FILE` in `.env`, and re-run the play.
